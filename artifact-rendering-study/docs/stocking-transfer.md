# 给丝袜项目保留的迁移知识

这份建议建立在 Saltline 源码与 `stocking-lab` 静态接口上。未改动目标项目；原作与独立实验运行见[实机报告](runtime-findings.md)，不代表丝袜项目视觉验收。

## 先迁移方法，再判断是否需要新效果

| 优先级 | Saltline 提供的具体方法 | 对丝袜有什么用 | 现有接口与后续判据 |
| --- | --- | --- | --- |
| P0 | `aRest` 材料域与语义遮罩 | 袜口、足尖、接缝、蕾丝和损伤区跟随同一块布，拉伸时纹理不游动 | 保留 fabric vertex/chart 与切线更新；对比抓取前后的同一针脚位置 |
| P0 | 真实尺寸的细节频率 + 屏幕导数足迹 | 防止针织与网眼因距离变化出现摩尔纹、闪烁和平均密度突变 | 复用 nylon 的已有 LOD/coverage/glint；统一毫米到材料坐标换算 |
| P0 | 细法线退出时补偿平均受光 | 远处仍保留纱线整体高光宽度，而不是突然变成光滑塑料 | 对照已有 normal variance/roughness 代码；后续移动镜头检验，不只看静帧 |
| P0 | 把直接灯光、IBL、曝光、调色分开 | 判断“丝感”究竟来自纱线 BRDF、环境亮带，还是曝光压缩 | 保存 clean 灯光预设；固定曝光，逐项开关；保留皮肤参考 |
| P1 | 一份状态共同驱动 albedo/roughness/normal | 把潮湿、局部摩擦、褶皱等组织成一致外观层 | 接入现有 appearance/optics 参数；不照搬金属、水膜或沥青数值 |
| P1 | 多个输出共享语义遮罩 | 同一破损状态同时作用颜色、覆盖、法线、深度与投影 | 保留现有破洞与阴影代理；检查真实洞口而不是只给颜色画黑点 |
| P1 | 柔和阴影、环境反射、温和高光压缩 | 让贴体曲面、薄纱和肤色关系更容易读 | 使用 Godot 原生同类能力先比较；避免 AO 把小间隙压黑 |
| P2 | 程序雨珠/缝线/罗纹 | 提供可选细节层，局部 roughness/bump 比统一噪声更可控 | 静态外观先独立开关；确需轮廓或接触变化才做几何/物理 |
| P2 | bloom、调色、暗角 | 为成品演示提供镜头风格 | 在 clean 材质已经成立后单独评估，保留关闭入口 |
| P3 | 平面反射、雨雾、flare、streak、grain | 用于展示场景与特定镜头 | 不是丝袜固有属性，不作为材料质量的必需条件 |

P0–P3 表示建议的研究顺序，不代表已经安排实施。详细源码与 Godot 对应分别见[材质报告](materials-and-textures.md)、[渲染迁移表](rendering-port-map.md)和[衣袖分析](surfaces-fx-and-cloth.md)。

## 物理解算与外观保持独立接口

Saltline 的衣袖微纹理、雨珠与标准受光不能提供丝袜受力、贴体、拉伸、撕裂或脱卸方案。它能提供的是“已经有了变形表面之后，如何让细节稳定地跟随并受光”。

建议继续让 `stocking-lab` 物理层输出位置、法线/切线、材料坐标、应变、密度、区域与损伤状态，再由外观层读取。拉伸可改变覆盖率与高光方向，但关系需要针对尼龙针织校准。不能用任意 alpha 淡化替代纱线稀疏，也不能用边缘 emission 替代受光 sheen。

各向异性材质、各向异性纹理过滤、镜头横向光条是三项独立功能。迁移时分别命名、分别开关，避免一个 `anisotropy` 滑块同时控制它们。

## Godot 的实施边界

现有 Forward+ 项目可以先沿用 `ShaderMaterial` 的 `fragment()`/`light()`、`WorldEnvironment`、灯光、sky radiance、SSAO、glow 和 LUT。源码的 `onBeforeCompile` 是 Three shader chunk 补丁接口，Godot 中应整理为 `.gdshader`/`.gdshaderinc`，不做字符串替换式照搬。

半透明前后层、洞口与阴影是先要解决的约束。Godot 普通屏幕纹理在透明之前抓取，最终镜头效果与透明层参与深度/SSAO/SSR 是不同问题。需要透明后自定义多 pass 时再设计 CompositorEffect；准确复制 tone mapping 后的效果需要额外核对输出颜色空间。见[Godot 参考](godot-reference.md)及其官方来源。

普通 fabric 材质或 Khronos sheen 参考图不等于丝袜模型。尼龙的方向高光、薄层透光、皮肤背景、针织空隙和变形尺度必须保留为单独的外观问题。

## 证据目标与当前覆盖

1. 保存原示例总览、材质 showcase、衣袖/手套近景、湿地反射和太阳雾光画面，并记录实际质量档、分辨率、相机和曝光。
2. 逐项关闭光照/后处理/细节，确认源码效果实际启用并排除 fallback。记录截图、配置和原件哈希关联。
3. 若需要，导出程序生成的颜色、ORM、高度和 normal，检查解码、均值、接缝与 mip 行为。运行生成之前不伪造这些资产。
4. 在独立 Godot 实验场景对照选中的单项方法，先固定姿态/灯光，再做近中远镜头和动态拉伸。普通 LOD、透明排序、切线方向与阴影同步分开验证。
5. 性能分别记录物理、数据上传、几何、透明 overdraw、阴影与后处理。不能把网页 `frame interval` 当作某个 GPU pass 的耗时。

原作运行、纹理/缓冲导出和独立Godot实验已经完成；以上丝袜特有的拉伸、洞口和排序验收仍未执行。是否采用某个视觉效果仍需画面对照和用户选择。
