# 原版游戏音频迁移方案

状态：**已完成原始缓冲导出和首轮 Godot 接线，听感与完整事件对照仍在进行。** 原作和衍生音频的公开范围尚待核实。

## 当前实现与验证

- 调用本地原版 HTML 中的生成器，导出 79 个生成项、136 个缓冲，其中包含 14 个循环和两个 48 kHz 混响脉冲；保留原始 Float32 数据、16 位交付 WAV 与哈希清单。16 位量化误差最大约为 0.00001526。
- Godot 已接入射击、换弹、切枪、脚步、弹壳、命中、爆炸、天气、敌人、菜单与任务事件；七条音乐循环使用同步流，按游戏状态调整声部，并在射击时降低音乐。默认总音量为 80%，设置可保存。正常入口使用系统音频设备。
- 资源和事件的自动检查通过：已加载 136 个缓冲及 14 个循环；实际游戏场景验证了音乐、空枪、金属脚步、弹壳和音量设置。隔离 PulseAudio 输出测试录到了原始枪声与脚步，测试样本峰值约 −1.9 dBFS。
- 总线使用 Godot 压缩器近似原版的 −3 dB 阈值、2:1 压缩比、10 ms 起音和 120 ms 释放，并使用限制器控制峰值；原版的 soft knee 和 waveshaper 不与此实现完全等价。
- **仍有差异：**Godot 使用内置算法混响，没有对原版脉冲做实时卷积；空间化、动态音乐的部分时序及环境事件还没有逐项等价实现。完整事件时序、混音、人耳听感和所有暂停/恢复路径尚未完成对照。音频已经可运行，不应称为与原版完全一致。

导出代码和清单位于 `tools/export_original_audio.cjs`、`saltline-godot/assets/audio/original/manifest.json`；可播放事件接线见 `saltline-godot/scripts/original_audio.gd`。自动化测试位于 `tools/tests/original_audio.test.cjs` 和 `saltline-godot/tools/tests/`。

## 原版有什么

原版声音不是一组待复制的 MP3。HTML 中的生成器按名称、变体和采样率合成音频，游戏运行时再按事件、位置和状态调度。静态清点得到 79 个生成项、136 个缓冲，其中两个缓冲为混响脉冲，另有 77 个可播放生成项、134 个可播放缓冲。另有七条同步音乐循环，以约 96 BPM 的节拍组织。数字是代码清点，实施时须用导出清单重新核实。[原版音频证据](source-evidence.md)

| 功能 | 原版机制 | Godot 迁移方向 |
| --- | --- | --- |
| 音色 | 程序生成枪械、人物、环境、交互和音乐缓冲；不同事件可选变体 | 调用原始生成器导出 Float32 PCM 与元数据；把可播放缓冲接入 Godot 音频资源 |
| 触发与位置 | 随动作、距离和位置播放，多个声音可并发 | 复用已有游戏事件，补充缺失的事件数据和弹壳触地信号；按位置与距离调度 |
| 配乐 | 多声部循环同步，并随游戏状态调整；射击时压低音乐 | 保持声部相位、循环长度、事件与总线行为；为状态切换和压低分别做验证 |
| 环境与混响 | 室内外使用不同脉冲响应，随位置和状态变化 | 对照原始脉冲及响应实现；若引擎内置混响不同，记录并测量差异，必要时评估卷积实现 |
| 界面与暂停 | 总音量设置约 80%；暂停后音乐、界面有各自行为 | 保留约 80% 默认总音量，提供 0–100% 可保存设置；暂停时保留原版对应行为 |
| 成片混音 | 不影响游戏设置 | 讲解时压低游戏音效与音乐，展示时适度回升；游戏原声与后期声音明确区分 |

## 需要特别处理的地方

1. **资源导出和精度。** 在隔离环境调用原版生成器，不用扬声器录音来冒充原始声音。保存名称、变体、采样率、时长、声道和哈希；保留原始 Float32 输出。若交付使用 16 位 WAV，比较量化误差和听感。导出脚本及资产的发布范围须另行核权。
2. **事件接线。** 当前已接出弹壳着地等主要事件；仍需逐一核对完整换弹、切枪、地表、敌人和目标触发条件与变体，不能由少量自动测试推断全部一致。
3. **随机数和时序。** 原版音色生成使用按名称和变体派生的随机序列，播放调度又使用与其他逻辑共享的随机来源。先记录调用和事件顺序，再做可重放对照；当前弹壳/掉落路径已消费过相关随机数，迁移时不得重复消费或无意改变画面、AI 和游戏状态。
4. **混音与音量。** 原版启动时的 gain 与设置值是覆盖关系，不能将 80% 再乘一次初始化值。暂停不能一概停止整个 `AudioServer`。实际混响、空间化及浏览器的输出表现可能与 Godot 不同，不能把内置效果直接称为等价实现。
5. **运行入口。** 旧复刻的正常运行及打包脚本强制使用 `Dummy` 音频驱动。新项目的正常入口需使用真实设备；自动化测试可继续显式选择 `Dummy`，避免打扰用户或依赖桌面设备。

## 验收矩阵

| 项目 | 核对方法 |
| --- | --- |
| 缓冲清单 | 比较生成项、变体、136 个缓冲、两个脉冲、时长、采样率和哈希；记录实际导出结果 |
| 调度 | 使用可重复的事件/随机输入，对照触发时间、声音名称、变体、音量、音调和循环；利用原版现有的室内/室外离线自检作为基线 |
| 游戏行为 | 实机检查射击、完整/中途换弹、切枪、弹壳前两次弹跳、不同地表移动、天气、命中、敌人、菜单、任务、死亡和重试 |
| 音乐与混响 | 检查七条循环同步、状态切换、射击压低、室内外尾音及暂停/恢复；记录无法完全匹配的部分 |
| 用户设置 | 验证默认约 80%、0–100% 调整、保存后重启与暂停时 UI 声音；确认真实设备正常输出 |
| 听感与视频 | 比较峰值、整体响度与削波情况，再人工试听原版和 Godot；录屏时检查讲解、游戏声与画面同步 |

数值与自动化检查只能定位差异，不能代替人对声音相似度和自然度的判断。若某项尚未完成，视频旁白和项目文档按实际情况说明，不把待实现内容说成已完成。
