# 制作与项目整合计划

状态：**脚本已确认；原版、Godot 和教学实验实录、合成旁白及完整视频已生成，自动技术检查完成；尚未发布，也尚未完成人工视听验收。** 下文保留原定计划；实际拍摄和验收结果以[录制证据](recording-evidence.md)、[验证记录](validation.md)及各专题记录为准。

## 已确定的目标

- 完整视频 8–12 分钟，开场 30–60 秒以 Godot 为主画面、原版为画中画，展示实时效果对比；后续讲解以原版和复刻左右并排为主。目标交付为 16:9、1920×1080、60 fps。
- 面向不了解或只了解基础 3D 的观众，采用轻松的科技科普语气。减少脱离画面的术语定义，所有技术原理均配合简洁 MG 动画，用纯色块、节点和箭头讲清输入、处理、问题与解决方法；保留必要的技术名称，在上下文和字幕中帮助理解。使用中文字幕和低音量配乐，优先迁移并使用原版程序化音乐和游戏音效，其公开使用须先核实授权。
- 直接陈述事实，技术章节主要按“原版有什么、Godot 如何复刻、遇到什么问题、如何解决”展开；章节采用“复刻光照效果”等直接标题。概览重点对比原作 Web 实现和 Godot 具体支持边界。展示三个由现有素材延伸的应用示例，并附 AI 可直接使用的简短提示词。
- 全片底部放半透明进度条，展示当前章节、章节分界和全片进度；避开字幕及游戏 HUD。片尾显示来源与未来公开项目首页的二维码，三连只用简短 MG 动画呈现，不口播。二维码在地址确定后生成并实际扫描核验；公开版本还要验证页面可供观众访问。
- 成片和录制的原始视频保留在新项目内。公开时根据授权与实际体积确定发行物或 Git LFS；不提前把大文件静默排除。
- 整合项目首发面向 Linux x86_64；提供经实测的运行入口与构建说明。Windows 和 macOS 不纳入本轮平台承诺。

## 开始制作前的审阅

先审 [旁白和分镜](../video/storyboard-script.md)、[三个应用示例与提示词](scene-and-ai-prompts.md)。旁白采用逐句可编辑的文本，每段同时记录画面、原版/复刻技术、证据和待拍镜头。素材权利、当前版本差异、音乐和二维码地址尚未确认的地方均明确标注。

用户已确认以当前脚本为基稿并同意开始实施。双端同步采集若无法稳定达到目标，可以分别实时录制并对齐、标明非同步操作。现有录像和静图只作为规划依据，不冒充本片新录素材。

## 实施顺序

1. **审阅脚本和本方案。** 已按反馈调整旁白、镜头和范围，并获用户确认。
2. **整理独立项目。** 核对两个源项目版本、文件来源和权利，将游戏、引擎补丁与研究资料整理进新目录；在隔离位置验证 Linux x86_64 的构建与启动。未核清公开权利的材料仅留本地或私有环境。
3. **补齐游戏与示例。** 按 [音频方案](audio-port-plan.md) 迁移原版游戏声音并对照；用已有素材完成三个应用场景。保留原版与 Godot 的对应关系及验证记录。
4. **录制与配音。** 先做短样片确认捕获能力、音画同步和实际帧率，再录制对照画面；使用 AW 选取参考片段、生成旁白小样并人工试听，满意后按段生成。把经验及本次实测边界整理进 AW 文档，并隔离提交。
5. **剪辑与验收。** 根据真实拍摄和迁移结果更新旁白，完成 MG、字幕、声音混合及章节进度条；交付原始录屏、剪辑工程、成片和资料，逐项检查并由人审阅。
6. **公开准备。** 逐项核实原作、音频、字体及其他资产的公开权利，决定有权再许可代码的协议和大文件分发方式。授权未清时交付本地或私有项目。私有预览片可在确认目标地址后放置经解码检查的二维码，并标注“项目待公开”；公开前另行验证二维码和页面的公众可访问性。

如实测无法稳定录制 1080p/60，先报告画面和帧率证据，再确定替代方案，不静默降低交付规格。

## 画面与动效方向

以港口画面为主，讲解图形使用深灰背景、暖白文字和琥珀色重点，小面积冷灰辅助；字体选择可公开使用且支持简体中文的字体，并保留来源与许可。MG 主要用纯色矩形、线条和文字解释相机、光线、材质及处理顺序，转场以约 0.25–0.45 秒的淡入和滑动为起点，避免闪烁和过度遮挡画面；实际节奏由样片调整。

片头以 Godot 实机为主画面，叠加原版实时画中画，位置可调整以避开 HUD；优先验证双端同时运行和同步采集。旁白开场说明原版由 Claude Fable 5.2 制作，并交代以 Godot 复刻探索引擎能力边界的目的。后续讲解采用左原版、右 Godot 的并排画面：在 1080p 画布上以各 960×540 的 16:9 窗口为基础，剩余空间用于逐句对应的 MG、标签和字幕，必要时增加对应位置的局部放大。新应用场景右侧明确标注为应用示例或教学实验；分镜示意不冒充真实运行数据。

全片进度条默认贴底，深色半透明底板承载当前章节标题、章节刻度与进度，字幕位于上方；遇到游戏 HUD 时调整布局，不遮挡准星和关键数值。颜色、字号和透明度以 1080p 实录可读性检查为准，而不是只看静态设计稿。

## 计划中的整合项目

目标是从一个新目录完成启动、学习和视频复用，而不依赖旁边恰好存在的两个旧仓库：

```text
satline-godot-oss/
  README.md                  用户入口和运行条件
  game/                      Godot 项目、场景、脚本、shader、必要资产
  engine/                    固定引擎来源、兼容补丁、构建和许可说明
  research/                  原作拆解、授权允许的源码/采集数据与参考图
  docs/                      上手、操作、渲染拆解、对照、AI 提示词与来源
  video/                     旁白、分镜、剪辑工程、字幕、章节与来源表
  media/                     本片原始录屏、成片及授权允许的媒体
  THIRD_PARTY_NOTICES.md     第三方来源、许可及保留署名
```

目录名称和最终布局可在整合验证时调整。保留游戏的 `res://` 资源关系；研究脚本原先引用同级目录的地方要逐一改为新布局并实测。原作源文件、贴图、网格、字体和外部参考图分别核查权利，不能用 Three.js 的 MIT 许可代替整部游戏的授权。自主编写且有权再许可的部分才选择对应开源协议；未经核实的材料暂留本地或私有环境。

按资产清单纳入运行必需的场景、脚本、几何和贴图，并保存原作来源、转换规则、哈希与必要验证。旧版本运行包和构建缓存不作为源项目内容；以固定引擎提交、补丁和构建说明替代本机环境。对观众提供明确的系统/GPU 需求、一条经过实测的启动路径、常见问题、可运行的示例场景及许可说明。最终从不依赖旧目录的新位置重新构建、启动和跑必要的关键效果检查。

## 原版游戏音频迁移

用户要求迁移原 HTML 音频并降低音量。静态检查表明，原版包含程序生成的枪声、环境、提示和多层音乐；声音还会随事件和游戏状态调度。旧 Godot 复刻有意排除了音效，启动脚本使用 Dummy 音频驱动。因此这是一项新增实现，不能只把一段原版背景音轨盖在无声画面上。

静态清点得到 79 个生成项、136 个缓冲，包含两个混响脉冲；其中 77 项为可播放音色，另有七条同步循环的音乐声部。缓冲现已导出并接入 Godot，自动事件与音频信号检查通过；原版与复刻的完整人工听感对照仍未完成。原版使用多条总线、空间衰减、室内外卷积混响、射击时音乐压低和随任务状态变化的配乐，暂停时音乐与 UI 仍有自己的行为。

脚本确认后先整理原作音频名称、生成方式、变体、采样率、音量、循环、位置、室内外及暂停/恢复规则。优先在授权允许的私有工作流程中从原始生成器导出可复用的 Float32 PCM 与元数据，再以 Godot 音频资源和播放调度连接实际游戏事件；对动态音乐、空间混音和混响等需要运行时行为的部分单独实现并验证。若 Godot 交付音频需要量化为 16 位 WAV，保留原始 Float32 数据并测量量化差异。保留对应关系、生成参数及哈希，明确哪些是忠实迁移、哪些是经听感确认的近似；原生 Reverb 不自动等价于原版卷积混响。是否能够完整复现所有规则，以后续逐项检查和实测为准。

当前静态拆解还发现三个接线风险：原版的音色生成和播放时随机数使用不同来源；复刻现有武器换弹事件没有保留原作决定声音变体所需的全部信息；弹壳着地尚无声音事件。实施时先建立源事件及随机调用表，补齐必要数据和信号，并检查已有弹壳/掉落逻辑是否已经消耗过对应随机数，避免重复消费或改变游戏行为。动态音乐、室内外尾音、空间位置和混响保留独立验证项。

游戏保留原版约 80% 的默认总音量；新增可保存的音量设置，允许用户在 0–100% 自行调节。原服务的初始化 gain 与设置值是覆盖关系，迁移时不能把两者再乘一次。只有视频采用单独的压低混音：讲解出现时压低游戏音乐和音效，转场或展示时可适度回升，避免枪声盖住讲解。优先使用原版音乐作为低音量背景，避免无必要地再叠一首外部音乐；其公开使用与原作资产一并核权。

验收包括 136 个生成缓冲的清点、原版自带室内/室外音频自检及真实触发的射击、换弹、移动、环境声、敌人、菜单、任务、动态音乐和暂停/恢复；分别比较原版与 Godot 的触发时序、变体、循环和音量，并做人工试听。暂停不能简单暂停整个 AudioServer：原版音乐和 UI 声音仍有各自行为。先用隔离测试避免录入其他应用的系统声音；游戏正常启动不能再强制 Dummy 驱动，自动测试仍可显式选择静音驱动。

具体接线、随机数风险和验收矩阵见 [原版游戏音频迁移方案](audio-port-plan.md)。

## 录屏与剪辑

1. 在脚本获准后，先验证当前桌面和窗口捕获权限，用 10 秒样片实测 1080p/60 的实际帧率、录音/画面同步及编码器可用性；60 fps 编码本身不证明实时达到 60 fps。现有环境有 FFmpeg，是否能可靠捕获当前 Wayland/XWayland 窗口仍需实际测试。录制范围限定于目标游戏与其声音，避免采集其他窗口、通知及其他应用的音频。
2. 片头优先尝试同时运行原版与复刻并同步采集实时画面，验证双端帧率和同步条件；若无法稳定实现，可分别实时录制后按场景和动作对齐，明确标注“非同步操作”。后续左右并排使用真实运行画面，保存版本、场景、相机、时间、质量、分辨率、曝光及采集方式。固定条件对照与自然实机操作分开标注，不声称两段不同操作逐帧同步。
3. 按脚本录制港口、湿地反射、室内光雾、材质、武器/敌人动作及三个应用示例。现有历史截图、旧视频和固定步进素材如被使用，标明版本和采集方式。
4. 使用项目现有视频工具完成镜头编排、MG 纯色图形、旁白、中文可编辑字幕和章节条。现有动效主要按 30 fps 编排，转为 60 fps 时必须检查时长和运动节奏。
5. 单独保存可编辑剪辑工程、字幕、原始录屏和成片；核对画面比例、音画同步、清晰度、中文文字、二维码、配乐授权和视频结尾。未经人工试听与观看，不把技术导出成功当作审美验收。

## AW 配音与自然度

用户已确认拥有本片声音克隆与合成讲解发布许可；原始声音样本和克隆数据不公开。工作材料与授权记录仅留在私有区域，公开内容只使用获准的最终讲解，并标注合成配音及模型来源。Higgs TTS 3 的实际许可要求真实人物的明确、可核实同意，并规定创作者内容的署名方式；发布前核对本地实际模型版本所对应的许可。[Higgs TTS 3 许可](https://huggingface.co/bosonai/higgs-tts-3-4b/blob/main/LICENSE)

本机 AW 的 `audio.tts` 使用参考音频、参考逐字稿和来源信息；当前接口的原始输出是 24 kHz 单声道，48 kHz 是后续重采样。原始样本含封面图片流，不能直接通过当前严格音频流检查。已保留原件并从选定音轨提取参考片段；具体参考和来源记录仅留私有工作区。

先从 2–3 段安静、单说话人、接近讲解语气的约 10–20 秒片段做候选，同一小段旁白逐一生成小样，比较清晰度、停顿、情绪、语速和跨句一致性。十秒量级只是[上游工具给出的起点](https://www.boson.ai/blog/higgs-voiceover)，不是当前样本一定合适的保证；[模型说明](https://huggingface.co/bosonai/higgs-tts-3-4b)强调准确参考逐字稿。由人试听确认后，再按可重做的独立段落生成并保留每段参数、原始 WAV 和版本。AW 当前没有公开的语速或情绪独立参数；不承诺未经实测的文本标签有效。

研究与本次实测结果整理到 AW 的 `docs/audio.md`；声音参考和克隆数据单独保存在本机私有目录。

## 事实与发布边界

- 原版基准是用户提供的本地 HTML；原 Artifact 链接与本地文件的一致性尚未验证。原游戏和采集资产的公开分发/再许可尚待核实；目前两个已有 GitHub 仓库均为私有。
- 复刻的高保真渲染使用定制 Godot 兼容构建；研究项目中的普通 Godot 实验是教学近似，不能混称为最终复刻。旧版 r16 不包含游戏音效；新整合版已接入原版生成的主要声音，但仍有混音和听感差异待核对。
- 室内历史对照曾出现明显局部差异，但属于旧版本和特定条件。制作阶段先重拍当前版本，再据实确定“差异较大”章节的镜头与结论。
- 脱敏检查覆盖本机用户名、主机路径、服务端口、凭据和声音参考；仓库、视频和说明分别检查。自主代码许可证待原作授权核实后选择。

## 交付与验收

交付物包括：可运行的整合项目、面向使用者的标准文档和来源/许可清单、可编辑旁白与分镜、中文学习文档、AI 提示词、原始录屏、剪辑工程、字幕、配音工作记录及带讲解的最终视频。每项记录对应版本和位置；公开分发与本地私有素材边界单独列出。

最终检查包括：独立位置运行游戏；抽查所有文档和资源链接；核验录屏实际帧率、成片规格、声音/字幕同步、章节条与二维码；复核原版/复刻和旧素材标签；记录用户对旁白、画面和声音的人工审阅结果。
