## 当前能力与前提

AW 的 `audio.tts` 支持 `clone` 模式，要求参考音频、与参考音频一致的逐字稿和来源。本次使用 AW 0.7.2、Higgs TTS 3 Q8_0、Linux NVIDIA CUDA，已完成实际推理；仅有模型和程序文件本身不能证明推理通过。

提供的音源含有额外的封面图片流。当前 AW 检查要求恰好一个音频流且没有其他流，因此需保留原件并从选定音轨提取仅含音频的参考 WAV。源文件、哈希、具体片段时间、参考逐字稿及授权记录仅留在私有工作区。

AW 默认生成参数为 `temperature=0.8`、`top_k=30`、`top_p=0.8`、`max_tokens=2048`、`text_chunk_size=40`。`seed` 不是音色 ID。当前 AW 接口没有独立的语速或情绪字段；上游模型文本标签在本机 AW 的支持及效果未验证。模型原始输出为 24 kHz 单声道；交付重采样到 48 kHz 不会凭空增加高频细节。

## 选参考片段

1. 确认已获说话人对本片克隆及发布的许可；用户已经确认该范围。原始音源和克隆数据不公开。
2. 保持原件不变，先从中寻找 2–3 段连续、单说话人、背景安静、情绪和语速接近讲解的片段。约 10–20 秒仅作候选起点，不假设原样本必然适合。
3. 明确提取音频流，检查是否有视频流、是否静音、削波和突兀噪声；逐字写出每段参考里实际说的话。不能用目标旁白替代参考逐字稿。
4. 用同一段 15–30 秒测试旁白及固定参数，分别生成候选小样。参考片段、文本、模型版本和参数一并记录，按随机种子生成可追溯版本。
5. 人工盲听并记录自然度、声音稳定性、停顿、语尾、中文数字与技术词发音；必要时替换片段或调整目标文本。技术检查和 ASR 可以辅助发现缺字，但不能代替人工试听或授权判断。

## 本片已执行的对照

在保留原件的前提下，以本机 Whisper base 对授权音源进行私有识别，选择了三段约 10–12 秒、自动识别置信度较高的候选；按音轨、起止时间和源哈希保存私有来源记录。参考逐字稿仍是自动识别候选，不能当成人工逐字核对完成。

三组候选使用同一段已确认的片头文本、相同 AW/Higgs 参数分别生成。生成结果经本机 Whisper base 再识别，将中文字符与目标文本作简单序列相似度比较，结果依次为 0.830、0.746、0.710。此分数只用于发现明显漏字或错字，不衡量声音相似度、自然度或授权；英语名称的识别也可能影响比较。当前暂用第一组生成正式段落，成片仍需人工试听，并根据结果替换或重做不自然的段落。

三次 AW 小样的技术结果均已生成，保留各次独立参考、参数、原始 24 kHz WAV 和 48 kHz 交付 WAV 在私有工作区；项目仓库不包含参考音频或克隆数据。

通用方法也整理在 AW 的 `docs/audio.md`；独立项目及私有声音记录不随本仓库分发。

## 让旁白更自然

- 先把书面长句改成口语短句；一次只解释一个概念。用标点和段落表达自然停顿，不依赖未经验证的语速、情绪或特殊标签。
- 对 `Godot`、`GPU`、`PCSS`、`IK`、`WebGL`、`Vulkan` 和采样次数等先做试听；误读时修改拼写或断句，不在未验证的前提下承诺某个音标技巧有效。
- 按 1–3 句或一个完整语义段分别生成，避免整篇长文失败后无法单段重做。AW 的内部 `text_chunk_size` 不是可独立恢复的已交付句子；显式分段任务、文本、参考、参数和 WAV 需要各自保留。
- 试听跨段的音量、呼吸感、语调和停顿。只有听起来突兀时才调整段落边界、补自然留白或做温和交叉淡化；响度处理不能修复不自然的语气。
- 比较同一参考下的少量参数/随机种子，而不是一次改很多变量。若样本主要是歌唱、嘈杂或多人对话，先说明其可能影响说话韵律，不承诺克隆后一定自然。
- 保留 AW 的原始 24 kHz WAV、后处理版本和最终混音。响度与峰值按交付环境测量，避免削波；目标值是技术参考，最后仍要由人听。

## 视频和项目的声音边界

原版游戏音频与 AW 合成旁白是两套来源。原游戏程序生成的音乐和音效已接入新版 Godot，游戏默认保留原版音量；成片讲解时再单独压低背景。原作音频的公开授权与游戏素材一起核实。

用户已确认本片克隆及合成讲解的发布许可。公开视频应清楚标注合成配音；使用 Higgs 创作者许可时，在视频或显著的随附说明中按许可标注 Boson AI's Higgs Audio。实际安装模型的来源、版本及适用许可需在制作前锁定，不把模型权重、声音参考或克隆数据作为开源资产打包。
