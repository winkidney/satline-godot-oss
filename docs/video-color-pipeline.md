# 视频录制与剪辑的颜色处理

本记录只讨论本片的 SDR 视频链路，不是原版与 Godot 画质的统一评分。一次旧版导出中，不同镜头的有限范围和全范围数据混在一起；拼接后的第二次编码使部分镜头的黑位抬升，影响观众对画面的比较。原始录像保留不变，问题在剪辑转换阶段修正。

## 输入判断

| 来源 | 原始记录与本片处理 | 边界 |
| --- | --- | --- |
| 原版浏览器 `original` / `original-frozen` | WebM 容器声明 full range / BT.709 矩阵 / sRGB 传递，但本机 VP8 解码帧报告 limited / BT.601；本片显式按容器的 full / BT.709 解码。 | 对 `props`，以录制约 3 秒处与另一次约 5 秒的原版 PNG 缩放到同一尺寸比较，整图 RGB8 MAE 分别为 2.865（full / 709）和 8.191（limited / 601）；主体区域分别为 3.575 和 9.798。两次时间和天气细节不完全同步；尚未通过浏览器播放 WebM 后读取像素独立核验。 |
| Godot 复刻实时录像、普通教学实验、正式游戏录像 | 视频没有完整颜色标记；按 RGB 屏幕捕获经 FFmpeg 默认转换到 YUV420P 的实际路径，采用 limited / BT.601 解码。 | 这是基于本机采集和默认转换行为的假设，不应按分辨率推断其他素材。 |
| 官方 Godot 调校录屏、重录海面与历史天空画面 | 解码帧标记 full range / BT.470BG（BT.601 矩阵）；显式按 full / BT.601 解码。 | 官方调校录屏与重录海面通过 Godot 逐帧输出，历史天空另行标注 720p；它们都不是实时帧率证明。 |
| 原版遮蔽示意、片尾卡 PNG | 以全范围 RGB 处理。 | 文字和二维码是图形叠加，不属于游戏画面。 |

每个输入先按各自范围和矩阵转换到 RGB，画中画及并排在 RGB 中合成；整个镜头最后转换为有限范围 YUV420P、BT.709 矩阵。所有镜头再以相同的颜色标记拼接，最终编码也使用相同标记。颜色传递标记为 sRGB（`iec61966-2-1`）：这里没有执行 sRGB 到 BT.709 传递曲线转换，不能把 BT.709 矩阵误写成完整的 BT.709 传递变换。缺失来源标记的桌面录屏按 SDR 屏幕内容处理。

## 可复核的检查

- 使用 `video/tools/check_film_color.py --shots-only` 比较同一帧的独立 RGB 解码与新镜头：原版、复刻和官方素材的主体区域 RGB8 平均误差分别约 1.383、1.444 和 1.423/255，包含缩放、4:2:0 与 H.264 编码误差。
- 两个不同来源的短镜头拼接实测中，镜头到无损拼接图的 RGB8 平均误差为 0；再次编码后分别为 0.138 和 0.951/255。它们用于发现编码链漂移，不证明整段动态逐像素一致。
- 最终成片完成后，不加 `--shots-only` 可逐项检查源素材到镜头，以及镜头、拼接画面和成片的抽样误差；当前结果见[版本 6 检查记录](../video/review/film-v6-color-qc.json)。这一过程检查转码和剪辑，不衡量跨引擎还原率。
- [FFmpeg scale 滤镜](https://ffmpeg.org/ffmpeg-filters.html#scale-1)用于矩阵与范围的实际转换；[setparams](https://ffmpeg.org/ffmpeg-filters.html#setparams)设置帧标记，本身不改变像素。FFmpeg [concat demuxer](https://ffmpeg.org/ffmpeg-formats.html#concat-1)要求输入流兼容，不能只看分辨率与帧率。
