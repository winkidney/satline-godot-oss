## 01:55–02:45｜Godot 的 PBR 能做到什么程度

**画面，样例与新录待审阅后制作**：

- `01:55–02:07` 独立官方 Godot 4.7.2 标准材质球，在相同光源和环境下调整金属度与粗糙度，再切清漆层及方向性高光；明确标“官方标准材质实验”。
- `02:07–02:18` 原版与 Godot 复刻左右并排，使用同一组砖墙和混凝土，分别从干切到湿。前期参考[已有干湿对照](pbr-comparisons.md#2-同一场景的干湿变化)；正式画面需复核条件并重录。
- `02:18–02:31` 用单独样例演示透明叠层和屏幕空间反射的局限；屏幕外物体与反射关系用 MG 辅助解释，再切回可见的真实画面。
- `02:31–02:36` 官方标准材质在固定条件下并排切换 Burley 和 Lambert 漫反射；差异以实测画面为准，不通过不同灯光放大差异。
- `02:36–02:45` 左右并排展示原版与 Godot 复刻的渲染工作台，叠加实际材质路线的示意。现有复刻球阵使用自定义 shader，不标为官方标准材质。

**旁白**：

> Godot 自带 PBR 材质，颜色、金属度、粗糙度和法线贴图可以表现漆面、金属与橡胶。调节粗糙度，高光也会跟着变化。
>
> 清漆层和方向性高光都有现成选项；皮肤散射需要 Forward 加。最终画面还受光源、反射和曝光影响。
>
> 透明叠层可能排序错误，屏幕空间反射看不到画面外的物体。原版湿地则使用镜像相机。
>
> 原版与 Godot 默认漫反射不同，Godot 可以切换模式。复刻用自定义着色器对齐光照和湿润，定制引擎适配湿地反射的斜裁剪。普通 PBR 不需要改引擎。

**MG**：逐步连接 `颜色 / 金属度 / 粗糙度 / 法线 → 表面受光`，球体并排显示参数变化；单独标出 `灯光 + 环境反射 + 曝光 → 最终画面`。原版 `Lambert 漫反射` 与官方 Godot `默认 Burley，可选 Lambert` 分支并列，接着展示 `原版局部 shader 修改 → Godot 自定义 shader`。反射示意同时画出 SSR 可见屏幕与镜像相机的观察范围；透明叠层展示排序问题。所有图解标“示意”。

**实现选择与对照边界**：这是项目为追求原作特定画面而选择的路径，普通 Godot PBR 不要求修改引擎。官方标准材质球、默认模型切换、透明及反射实验均待制作并标注版本与条件，不能用现有定制复刻截图冒充；原版与复刻画面分开实录、标注“非同步操作”。四组新增对照及条件见 [效果对比](pbr-comparisons.md)，详细依据见 [PBR 调查](godot-pbr-investigation.md)。

## 02:45–04:14｜复刻天空与海面

**画面，新录**：

- `02:45–02:58` 原版与 Godot 从港口抬头，展示太阳周围云层与远处天际线。
- `02:58–03:11` 固定机位看云层随时间变化；如以受控方式触发雷电，显示“受控触发”。
- `03:11–03:22` 船体升沉、吊具摆动、雷达旋转和远处海鸟，与敌方 Gull 分开标注。
- `03:22–03:46` 主场景岸边和开阔海面，分别拍大波轮廓、阳光碎亮及船边泡沫。
- `03:46–04:14` 低角度看近岸细波；左右对照后接 MG，再回到真实海面。已有 720p 历史片仅用于选镜，正式镜头待重录。

**旁白**：

> 原版天空里的云不是一张永远不动的图片。程序把多层变化的噪声组合起来，再根据太阳方向调整明暗和云边颜色；雷电出现时，天空还会按方向短暂闪亮。可见云层持续变化，环境反射则使用初始化时捕获的天空环境图。
>
> Godot 复刻保留了这套天空计算。最初，两种图形后端对噪声纹理的插值存在细小差别，经过多次叠加后，云色偏差被放大。改为显式计算插值后，九十六组受控采样通过了对照；这说明被测采样点接近，不代表所有天气画面完全一致。
>
> 港口背景也有容易忽略的动态：货轮轻微升沉，吊具摆动，雷达转动，远处还有装饰海鸟。船只的展示动画不等于玩家可以驾驶。
>
> 海面则把大浪和细波分开处理。大波推动网格改变轮廓，细波和流动纹理改变表面的受光方向；靠近码头和船体时，再根据距离生成泡沫和污沫。
>
> Godot 沿用了波形与表面规则，并接入环境反射和太阳高光。这里的海面与后面讲的湿地倒影使用不同路径，不能把两者当成同一种镜像反射。

**MG**：

1. `噪声层 + 时间 + 太阳方向 → 云色与雷光`，用平面云片和闪光示意。
2. `采样位置 → 显式插值 → 对照结果`，旁边标注“96 组受控输入”。
3. `大波 → 网格轮廓`、`细波 → 表面受光`、`岸边距离 → 泡沫`，再区分海面环境反射与湿地镜像相机。

**依据与边界**：[天空实现和 96 组采样](../../saltline-godot/docs/sky.md)、[海面实现与历史适配边界](../../saltline-godot/docs/sea.md)、[背景动态](../../saltline-godot/docs/source-backdrop.md)。旧阶段的未完成表述不能自动当成当前版本缺陷；当前画面和交互需重拍复核。

## 04:14–05:00｜复刻光照效果

**画面，新录**：左右展示仓库穿窗光束及 `render` 工作台的遮挡墙；分别切换可对照的雾或阴影状态。镜头从全景进入墙边，观察光束是否越过遮挡。

**旁白**：

> 仓库光束来自体积光。原版在高画质下先在半分辨率画面上沿视线取二十四个点，逐点判断太阳有没有被挡住，再累计雾中的散射光与透光率。
>
> 结果经过两次参考深度的模糊，再合回原画，避免光糊到墙后。太阳阴影另用 PCSS，先寻找遮挡物，再根据距离调整柔边。
>
> Godot 将体积光和表面阴影分别接回渲染流程。雾层需要保留透光率通道；使用透明背景、关闭混合并保留浮点通道，可以避免合成时丢失这份信息。

**MG**：相机到墙之间依次出现采样点；散射和透光率进入“深度引导模糊 × 2”；地面阴影另画遮挡搜索与柔边。透光率丢失画成需要避免的配置问题，不说成已经发生的故障。

**依据**：[体积光与太阳阴影](../../docs/source-evidence.md)。

## 05:00–06:24｜复刻倒影与湿润

**画面，新录**：`ground` 工作台先拍干燥、湿润无镜像、湿润有镜像，再切主场景水迹和集装箱倒影；原版与 Godot 分别切换并标注。插入独立测试中 SSR 与镜像相机的对照，让被反射物移出主镜头，观察倒影变化。显示斜裁剪历史问题时注明历史版本。

**旁白**：

> 湿地上的清晰倒影来自第二台相机。原版把主相机沿地面镜像，再渲染一次场景；斜裁剪排除水面下不该出现的部分。反射图还会准备不同模糊程度的版本，供积水和粗糙地面分别使用。
>
> Godot 的屏幕空间反射依赖当前画面，镜头看不到的物体不会出现在这部分反射中。复刻选择镜像相机，是为了更接近原版的倒影范围。
>
> 搬到 Godot 时，这种斜投影曾让部分灯光和阴影计算用到的相机范围异常。复刻版修改引擎兼容路径：实际绘制继续使用斜投影，灯光范围计算使用正常的参考投影。
>
> 同一份湿润状态还会改变地面颜色、粗糙度、细小凹凸和倒影权重。积水更清晰，只有潮气的地方则更散。雨圈、水珠和倒影共同构成湿润的视觉效果，并不是逐滴水都做完整物理求解。
>
> 一些雨珠位置最初没有对上，原因涉及噪声计算中间值的精度和舍入。固定关键计算步骤后，四十八组受控输入通过比较；这不是对整个场景逐像素一致的保证。

**MG**：对比 SSR 的屏幕范围与镜像相机可捕获的范围，再画主相机翻转、斜裁剪、反射清晰度分层；把“实际绘制投影”和“灯光范围参考投影”画成两路。湿润状态分支驱动颜色、粗糙度、微凹凸与倒影，最后显示噪声输入和固定舍入点。

**依据**：[反射与湿润对应关系](../../docs/source-evidence.md)。原海面在上一章单独解释。

## 06:24–07:33｜复刻布料与武器材质

**画面，新录**：`mats` 全景及金属、玻璃、织物、锈蚀近景；`hands` 工作台展示袖口、缝线和水珠；`weapon` 工作台展示枪身侧面、瞄具、磨损及高光。独立微细节过滤实验单独标注“教学实验”。

**旁白**：

> 袖口的织纹、缝线和雨珠则使用手臂变形前的材料坐标。手臂移动时，花纹跟着表面走，不会因为角色换了位置就在皮肤上滑动。Godot 复刻把这套规则接到了材质里。
>
> 细织纹远到小于屏幕像素时容易闪烁。独立实验用屏幕导数判断细节大小，逐渐淡出细纹，并通过粗糙度保留平均高光。这是视觉近似，不代表已经完成丝袜光学或布料物理。
>
> 枪身高光还暴露过另一个问题。WebGL 与 Vulkan 的屏幕方向和多重采样覆盖方式不同，一些细小三角形会影响局部亮点。定制引擎调整了视口光栅方向，并同步处理正反面、颜色和深度读取。
>
> 在一个历史固定机位的武器样本中，RGB 八位平均颜色差从约零点五六降到零点二三；它只是该样本的对照数值，不是整个游戏的还原率。

**MG**：材质配方分出颜色、属性、高度与法线，再通过导出箭头连接 Godot 材质；材料坐标网格随手臂弯曲；细线缩小到像素以下后渐隐并转入粗糙度；最后画细三角形与采样点，显示“历史受控样本 0.56 → 0.23”。

**依据**：[材质与纹理](../../artifact-rendering-study/docs/materials-and-textures.md)、[程序生成与导出重建的源码核查](procedural-source-verification.md)、[原版/Godot 对应](../../docs/source-evidence.md)、[丝袜应用边界](../../docs/scene-and-ai-prompts.md)。

## 07:33–08:46｜复刻武器与敌人动作

**画面，新录**：

- `07:33–07:51` 武器工作台侧面和第一人称换弹；展示手抓弹匣、手腕与手指变化。
- `07:51–08:11` 机械犬近景：站立、转向、迈步、瞄准及受击；尽量给脚部落点足够画面。
- `08:11–08:31` Gull 无人机近景：旋翼、云台、扫描、飞行和受击坠落；受控触发单独标注。
- `08:31–08:46` 回到港口实战，穿插中继交互和到撤离点的路径；不把抵达小艇附近说成驾驶小艇。

**旁白**：

> 换弹时，弹匣、枪和手臂不是各播各的动画。原版先更新枪的惯性和弹匣轨迹，再根据握持目标求解肩膀、手肘和手腕，让手跟着弹匣移动。
>
> Godot 把这些计算接到实时骨骼上。如果旧手臂动画和实时求解同时写入同一组骨骼，结果可能被覆盖；复刻版跳过冲突的旧手臂轨道，统一由实时求解写入。
>
> 四足机械犬的脚步也会根据身体移动和地面落点计算。身体转向、抬脚和落脚配合，组成看起来有重量的运动；远处的敌人不是简单沿路径滑行。
>
> 飞行敌人 Gull 则组合了飞行路径、四个旋翼、云台、扫描和攻击状态。击中后还能看到失稳、坠落与爆炸。演示镜头如果使用脚本辅助，会在画面中标明。
>
> 正常任务围绕三个中继点展开，全部关闭后前往小艇附近的撤离区域。实际手感和战斗表现仍需要游玩判断。

**MG**：`弹匣轨迹 → 握持点 → 手臂骨骼`；旧动画与实时求解汇入同一骨骼时显示冲突，再移除旧轨道。机械犬显示身体、落脚点与腿部关节；无人机显示机身、旋翼、云台和状态流。均标“示意”。

**依据**：[敌人迁移](../../saltline-godot/docs/enemy-implementation.md)、[任务状态链](../../saltline-godot/docs/full-mission-native-chain.md)。部分历史片使用受控操作，仅供选镜。

## 08:46–09:23｜复刻曝光与后处理

**画面，新录**：原版和 Godot 分别从亮处走入仓库、再转向窗外；接 `render` 工作台的高光球、发光体及后处理状态，记录曝光与触发条件。

**旁白**：

> 从明亮的码头走进屋里，画面不会立刻切换到另一种亮度。原版在画面上取三十五个测光点，中央权重更高，再结合上一帧结果，用大约一点五秒平滑调整曝光。
>
> 泛光、横向光条和最终调色也有固定顺序。Godot 按对应顺序接回这些步骤；曝光历史曾出现逐帧累积偏差，处理方式是在写入历史之前按原版方式舍入，避免小误差反复积累。

**MG**：画面上显示少量示意测光点并注明“实际 35 点”；中心点连接历史亮度和平滑曲线，再画亮部、泛光、光条、曝光与输出的处理顺序。

**依据**：[曝光与后处理记录](../../docs/source-evidence.md)。

## 09:23–10:11｜复刻战斗与环境特效

**画面，新录**：`fx` 工作台的曳光、弹着、火花和爆炸；主游戏中拍枪口、弹壳、油桶爆炸和墙面弹痕。原版和 Godot 采用尽量接近的触发与镜头，仍标注非同步操作。

**旁白**：

> 一次命中或爆炸不是单独一张特效图。枪口闪光、曳光、火花、烟雾、碎片和短暂照亮周围的灯光，会按各自的寿命和方向组合。
>
> 原版把烟雾和亮光分别组织，并参考场景深度，让粒子贴近地面或墙面时逐渐淡开。Godot 复刻使用粒子池与自定义 shader 接回这些规则；弹壳和碎片采用各自的运动和简化弹跳。
>
> 两边的随机过程、触发时刻和渲染历史可能不同。重拍时先对齐触发条件，再讨论具体画面差异，不把相似的一帧当成完整动态一致。

**MG**：一个爆炸事件分出烟、火、火花、碎片与短时灯光；粒子接近墙时，深度线控制交界处淡出。背景实录持续播放，不只保留静态图。

**依据**：[原版特效拆解](../../artifact-rendering-study/docs/surfaces-fx-and-cloth.md)、[Godot FX 工作台](../../saltline-godot/docs/fx-showcase.md)。

## 10:11–11:03｜复刻技术的应用

**画面，新录**：依次使用现有港口湿地、海面/天空、仓库和独立织纹实验。左右画面分别标明原版参考与 Godot 应用或教学实验；每个例子叠一条短提示词。

**旁白**：

> 这些做法可以拆开用于其他游戏。雨后街道可以让一份湿润状态同时控制颜色、粗糙度和倒影，再用干湿开关检查变化。
>
> 海岸场景可以把影响轮廓的大浪、影响高光的小波和岸边泡沫分开调整；天空则先确定太阳方向，再组织云层和远处雾色。
>
> 室内先固定窗、墙和光源，再加入受遮挡的雾。角色衣物则要让纹理跟着表面运动，并检查远处是否闪烁。
>
> 丝袜还需要单独处理皮肤透出、纱线方向、破洞和物理变形。每个例子的输入、目标和验证方式，都可以整理成供 AI 参考的提示词。

**屏幕短提示词 / MG**：每次只显示一条，完整文本保存在文档。

1. `湿润状态 → 底色、粗糙度、倒影；保存干湿对照`
2. `大波轮廓 + 细波高光 + 岸边泡沫；固定机位比较`
3. `固定墙窗与光源 → 加入受遮挡的雾；拍开关对照`
4. `织纹跟随表面 → 按远近过滤；检查运动闪烁`

**依据**：[现有应用案例与完整提示词](../../docs/scene-and-ai-prompts.md)。海与天空的完整提示词待本稿确认后补入项目文档。
