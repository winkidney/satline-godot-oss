原版许多模型按程序参数组合，很多基础贴图由 GPU 生成缓存；复刻使用导出资产重建，动态天空、海面、湿润和动作仍由程序计算。官方 Godot 对照中的灯光、天空和部分动态为近似，不能把差异全部归因于材质。

字幕去标点并以空格分隔；透明底色的纯色 MG 展示原理，底栏两行展示全部章节并高亮当前章节。原游戏音量不变，仅在成片中压低。末尾仅用简短三连动画。

## 04:17–05:44｜复刻倒影与湿润

**画面：** ground 原版 对 复刻；ground 复刻 对 官方内建；官方内建 SSR 与湿度近似；ground 对照细节。

**MG：** 主相机 → 地面镜像 → 斜裁剪；湿润状态 → 底色 粗糙度 微凹凸 倒影；实际绘制投影 与 灯光范围投影 分开；固定天气烘焙贴图 → 屏幕空间反射；精度与舍入不同 → 噪声偏差 → 固定精度重算。

**实际镜头：**

- 04:16.67–04:36.08 ground：原版 HTML · 调试场景 / Godot 复刻 · 固定步进
- 04:36.08–04:49.37 ground：Godot 复刻 · 固定步进 / 官方 Godot · 烘焙湿地与 SSR · 固定步进
- 04:49.37–05:13.68 ground：原版 HTML · 调试场景 / Godot 复刻 · 固定步进
- 05:13.68–05:20.20 ground：Godot 复刻 · 固定步进 / 官方 Godot · 烘焙湿地与 SSR · 固定步进
- 05:20.20–05:44.20 ground：原版 HTML · 调试场景 / Godot 复刻 · 固定步进

**旁白：**

> 地上的倒影来自第二台相机：原版把主相机沿地面镜像，再渲染一次场景。镜像相机使用斜裁剪，排除水面下不该出现的部分；反射图还会生成不同模糊程度的版本，供粗糙和积水的地面分别采样。
>
> 官方内建画面使用原版湿地程序在固定天气下烘焙的贴图，再配合屏幕空间反射。它看不到屏幕外的反射物，积水和细波也不会随天气实时变化。
>
> 搬到 Godot 时，斜裁剪让部分灯光和阴影计算用到的相机范围出了问题，一度出现报错和阴影异常。最后修改了引擎兼容路径：实际绘制仍用斜裁剪，灯光范围计算使用另一套正常的参考投影。
>
> 原版把湿润程度作为一份共同状态，分别调整底色、粗糙度、细小凹凸和倒影权重。积水处的反射更清晰，只是潮湿的地方则更散。
>
> 雨水边界曾在两种图形后端出现不同形状，原因是地面噪声中间计算的精度与舍入不同。
>
> 修复方式是在关键中间值固定浮点精度和舍入点。四十八组受控输入重新比较后通过；这只能说明这组噪声计算对齐了，不代表所有地面画面都完全一致。
>

>
> 在一个固定机位的武器画面里，平均颜色差从大约零点五六降到零点二三。这只是该画面的对比数字，不能当作整个游戏的还原率。

> 曝光历史的移植曾出现逐帧累积偏差：当时 WebGL 参考和 Vulkan 后端对半精度数值的舍入结果不同。修复是在写入历史之前按原版方式舍入，避免小误差一帧帧积累。
